# Team 用户与成员头像实施记录

## 目标

- 在 Bingo Go 中接入 12 个可复现的几何头像，并保留已有 8 个头像 ID。
- 用户头像在 Bingo Go 的“个人资料”设置中持久化；固定成员头像继续写入 `.bingo/team.json`。
- Team 大厅、任务群聊和普通频道按发言人显示头像。

## 范围与非目标

- 修改 Bingo Go 的用户资料存储、IPC、设置页、成员编辑器和 Team 消息布局。
- Bingo 当前分支已有 `team.avatar.read.v1` 与 `team.avatar.get`，本轮将其作为兼容前置条件，不再修改 Bingo 后端。
- 不修改普通一对一 Chat 的布局，不增加昵称，不把用户自定义头像写入项目或团队预设。

## 实施阶段

1. 生成并同步 `identicon-01` 至 `identicon-12`，补充资源校验与说明。
2. 在 Bingo Go 中增加版本化用户资料存储、头像上传归一化、IPC 与全局 Provider。
3. 增加头像选择器，接入成员详情、蓝图、侧栏、检查器和三类 Team 会话。
4. 补齐兼容性与 UI 测试，运行前端完整验证。

## 兼容与数据风险

- 原有头像 ID 和顺序保持不变；Team schema 与协议版本不升级。
- 旧成员缺少头像时只显示稳定几何兜底，读取项目不会改写 Git 文件。
- 新成员与首次用户资料初始化只随机一次，并立即写入各自持久化配置。
- 用户上传图片限制为 20 MiB，归一化为 512x512 PNG；项目头像仍由 Bingo 管理。
- 所有配置写入继续使用 revision 冲突检测、备份和原子替换。

## 验证

- Bingo Go：`npm run test`、`npm run typecheck`、`npm run build`。
- 协议兼容：确认当前 Bingo 仍声明 `team.avatar.read.v1` 并响应 `team.avatar.get`；旧 Bingo 缺少能力时使用稳定几何兜底。
- 重点覆盖头像资源可解码、默认分配、路径安全、资料冲突、上传校验、消息左右布局和 800x600 样式约束。

## 假设

- 新增 12 个几何头像作为默认池，原有 8 个头像继续可选。
- 临时成员在固定前只显示兜底头像，固定后获得持久化的随机几何头像。
- 普通 Team 频道中的 `main` 使用稳定几何头像；系统事件不显示头像。
